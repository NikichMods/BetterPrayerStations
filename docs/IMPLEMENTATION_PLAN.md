## First technical slice

Hypothesis: stable grave state plus a narrow native rating/UI extension can represent the agreed effective changes without modifying physical bodies; two grave-owned appearance codes can drive world rendering independently of physical decoration quality.

Start with the shared evidence linked in `EVIDENCE_AND_ACCEPTANCE.md`. Verify the still-open owners rather than repeat the completed economy/player-needs research. Establish:

1. Stable grave identity and save/load lifecycle, including an empty/reused grave.
2. The narrow native effective-rating/display seam; actual body/organ data must remain untouched. Static owners, a proposed grave-call-site projection and a 160-case native decay oracle are recorded in [FAITH_IMPROVEMENTS_RESEARCH.md](FAITH_IMPROVEMENTS_RESEARCH.md). Native decay for converted whites is adopted; the authorized `research/FaithProbe` provides the separate session-only rating/diagram/explicit-activation candidate, with no spending or radius. Faith Probe0.1.1 now passes the bounded native rating/diagram/explicit-activation/cleanup slice; saved investment/body replacement now have2700-case native-getter and native binary serialization evidence on synthetic owners. Faith Probe0.2.0 now confirms empty/replacement-body investment recovery across two menu-loads, decayed replacement calculation and saved cleanup. Live destination non-export was not instrumented; payment, coverage and production migration remain unverified.
3. Prayer-station coverage geometry and reliable relevant placement/movement/removal updates, without a recurring full-world scan.
4. Grave-slot appearance persistence: set two appearances -> save/load -> remove/reinstall decorations -> move a physical decoration to a different grave. Source grave choices persist, empty slots stay empty, destination choices apply, and real item quality remains native.
5. [Native rendering owner](APPEARANCE_RENDERING_RESEARCH.md): descriptor projection is the supported research direction. The narrow installed 0.1.1 refresh/close/menu-load and two loaded looks pass; 0.1.2 also passes both-slot native removal/reinstallation and distinguishable gravestone exchange/menu-load. Remaining production boundaries and limitations are in the rendering research; no production mutation is yet accepted.

If the grave identity or appearance-rendering hypothesis fails, select another mechanism with explicit evidence rather than reduce the product requirement by accident. Do not design a generic persistence/UI framework before the concrete lifecycle is known.
