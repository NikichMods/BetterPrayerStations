# Station menu presentation proposal —2026-10-26

Status: **Родной список layout adopted; copy/icons pending**. User approves the native-list layout and requests understandable in-world prayer/blessing terminology. "Поддержка молелен" is rejected as insufficiently immediate. Beam art remains deferred; native rendering/implementation is not accepted by this preview approval. The original recommendation/labels below are historical proposal context, not final copy.

Current unadopted copy: "Помолиться" / "Благословить место" / "Снять благословение". Prayer grants one more permanent blessing; removing a positioned blessing retains the granted investment. "Место" preserves adopted free ground placement; "могилу" alone would imply a new targeting restriction. Proposed ledger "Даровано благословений: P" / "Молельни: до C благословений" / active/free counts with conditional dormant count. No new grace/power resource or upkeep. Native faith icon for prayer/price and a lit/unlit ground-blessing icon pair are proposed; exact native asset availability or new small sprites remain to inspect, not assumed. Copy/icons/density require feedback before adoption.

Recommended variant: **Родной список**. Retain the established native three-card family instead of adding tabs or a dashboard. Header "Благословения"; a compact ledger separates "Куплено мест: P" and "Поддержка молелен: C". Do not render P/C as one fraction: P>C is a supported state, not invalid progress. Below, a secondary line shows "Размещено: N · Свободно: F"; only when support is insufficient replace this with active/dormant/free counts. Prices belong to the buy card, not repeated in the header. Native ingredient icon and required faith count should carry price, with available faith beside/below or via the established native tooltip depending on real fit.

Three rows: "Купить место" (+1 cemetery capacity; price/available faith), "Поставить свет" ("На могиле превращает все красные черепа в белые."), "Убрать свет" (free; purchased places retained). One quiet footer states common places/price for all stations. Unavailable buy retains the visible price and states shortage of faith or station support; unavailable placement identifies no free capacity or lost support. Removing dormant points stays available. The any-grave-cell conversion rule must still remain visible throughout the actual world placement mode, independently of this menu. No new payment, placement or activation rules.

Alternative for comparison only: **Акцент на размещении** — place is the large first row, buy/remove are smaller side-by-side actions. More emphasis on repeat use, but requires more departure from the already proven native list/focus/layout ownership. Prefer the native list unless user feedback favors the alternative strongly enough to justify that implementation research.

Interactive preview includes ordinary, insufficient faith, insufficient support, all places occupied and initial-state cases, plus ordinary/compact density. Purchase updates local illustrative counts/faith; Place/Remove show only the transition boundary to the cemetery grid. Geometry, colors and icon placeholders are an approximation, not extracted or verified native rendering. Actual implementation should use native frame/sprites/font/faith icon and verify text wrapping, row minimum height/redraw, description anchors, disabled reason and mouse/gamepad focus; current accepted functional evidence does not close the known repeated-redraw card-height defect. No full custom window is selected.

Preview QA uses an isolated browser: local purchase/state changes, insufficient faith, support/dormant removal, placement/back and no horizontal overflow at narrow/desktop widths. This verifies the preview only. Pending user choice: list versus placement emphasis, wording and density. On adoption, promote selected presentation into DESIGN and plan a narrow native-layout implementation/readiness pass. Do not treat this proposal as a selected final design.
