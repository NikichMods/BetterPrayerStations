# Better Prayer Stations — Faith Probe0.8.0

Research-only passive-quality candidate. Exact frozen source/hash/install: docs/TEST_BUILD_LOG.md. Not a production release; installed acceptance pending. Keeps accepted0.7.1 geometry/faith preview and earlier purchase/persistence backend. New passive contribution uses only committed stations/positions; its prospective allocation is deliberately not previewed in this slice.

## Короткая проверка — без веры и без назначения могил

1. Загрузите игру с готовой молельней рядом с могилами. **Назначать A/B, покупать улучшения или делать C1/L1 не нужно.** В панели у каждой молельни появятся число учитываемых положительных могил, сумма, бонус, обычная база и итог. Над самой молельней должен отображаться итог с бонусом. За полные10 качества добавляется1; например21 -> +2. Размеры пока диагностические: дерево18×18, камень24×24 маленьких клеток.
2. Нажмите **«Записать вклад могил и проверить зону»**, закройте обычные игровые окна и предпросмотр, если открыты. Дождитесь строки «Зона проверена: ...». Пробник сам запишет владельца каждой могилы, положительную сумму и сверит реальный итог/событие зоны — вручную считать не нужно. Если у молельни пока меньше10, можно выбрать другое место через обычное строительство/Move Objects, чтобы наблюдать ненулевой бонус.
3. При необходимости выдайте материалы кнопкой дерева/камня и постройте вторую молельню так, чтобы области пересекались и рядом были хорошие могилы. Строительный проект ещё не получает вклад; после достройки суммы обеих молелен пересчитываются. **Снова нажмите запись/проверку зоны.** Каждая положительная могила может принадлежать только одной молельне. Округление отдельно для каждой: распределение19+18 даёт +1 и +1, а не общий +3 — это нормально.
4. С Move Objects: начните перенос одной молельни, поводите и отмените. Пассивные суммы в этом пробнике остаются привязаны к подтверждённым позициям; жёлтая область и предпросмотр улучшений могил работают как раньше. Затем подтвердите перенос подальше от могил и обратно. После каждого подтверждения запишите вклад/проверьте зону: вклад перераспределяется между готовыми молельнями, счётчик не растёт. **Предварительный пассивный бонус по жёлтому квадрату пока не оцениваем.** Без Move Objects этот пункт можно пропустить.
5. Обычным способом снесите добавленную молельню и снова запишите вклад/проверьте зону: оставшаяся должна получить положенные ей могилы. Снос и достройка — нативные действия; чистая среда без Move Objects отдельно не считается принятой только из этого сценария.
6. Нажмите **«Отключить пассивный бонус до загрузки»**. Должны вернуться обычные качества молелен и общая сумма без этой прибавки. Бонус не хранится как отдельное улучшение: при следующей загрузке он пересчитывается по могилам и молельням. Для отката реальных построек/выданных материалов можно выйти без сохранения. Если отдельно меняли C/L, их очищает прежняя кнопка очистки могил; пассивное отключение их не удаляет.

Если пробник сообщает об отключении после ошибки — остановите сценарий, сообщите, на каком действии это произошло; агент прочитает доступный свежий журнал. F8 скрывает панель и тестовую область. Радиус/подсветка остаются диагностическими, не окончательным интерфейсом. Оплату/анатомию повторять не требуется.

## Mechanism and limits

ContributionMath chooses exactly one eligible same-zone station by squared center distance then persistent ID; inclusive square membership. PassiveQuality reads cached completed station and real grave refs, no scene/world rescans. Only positive current committed grave quality is accumulated; stations and unrelated zone objects never enter the contribution. Center/boxes and world registration reuse accepted0.7.1. Temporary CommittedOnly selection is restored in finally; passive contribution does not follow a floating source. Same grave service coverage remains nonexclusive. Aggregates reset each rebuild, no saved bonus/incremental ledger.

Numeric snapshots refresh at most4Hz in LateUpdate and immediately before native GetTotalQuality for a station's actual zone. Native station get_quality postfix only adds its cached bonus to the untouched native result; it never enumerates graves or calls the zone. Existing native quality-only badge path now also refreshes completed station labels on changed actual value. Descriptive output (base/bonus/total) reads station quality only after allocation; it is not a contribution input. Actual native zone member sum and OnQualityComputed stay authoritative. No direct player/save/resource/zone-total write and no synthetic total.

Explicit closed-window observer sums native member leaves with only station addition temporarily suppressed, restores it, then calls the actual GetTotalQuality once under its real native event. Expected difference is the summed station additions on actual nonignored members. It verifies total/event, money/faith and any assigned grave physical data; full per-grave owner trace supports independent inspection. It never fires a disabled-baseline total event. Old two-grave zone observer routes to the new passive observer while enabled; original old path remains when passive is off.

Offline checks cover actual compiled allocation helper (thresholds, positive-only, square boundary, stable tie/order, same-zone restriction, overlap unique sums and per-station floor, relocation/return), compiled nonrecursive getter/collector route and all earlier native160/2700 skull/rating, serializer, payment, source-preview/native badge gates. Runtime getter/Harmony, actual exclusive distribution, quality badge/HUD/native zone contribution, demolition/build transitions and performance are not accepted by compilation alone. No new final UI, passive preview, saved-schema, cap or production release in this candidate.

Native save-slot quality summaries may naturally observe the modified total through the host's existing getter; the probe does not create a saved bonus field or write a parallel authoritative quality value. Disable before comparing vanilla metadata; no claim that ordinary native save-summary fields ignore gameplay quality.
