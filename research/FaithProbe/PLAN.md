# Faith Probe 0.2.0 — research-method checkpoint

Question: does grave-owned investment survive native body removal/replacement and save/load without exporting to the body or losing its shared action progression?

Existing accepted0.1.1 evidence already establishes one-grave native rating/central-diagram projection, excess-red bound, explicit activation and unchanged anatomy. Do not repeat that complete scenario. Native grave parameters and the serializer are verified carriers; current source/native IL establishes item reuse across grave object transitions. What remains requires live native exhumation, rebury and scene restore.

Mechanism: three diagnostic parameters on root grave Item, C/L plus schema1; N=C+L. Current body is read dynamically. Only selected idle occupied grave receives input projection. Empty grave native result is unchanged. Existing WorldMap.objs is traversed once after game-started restoration, no recurring scan. Counts12 each are test bounds; explicit activation resets enabled on load. Production payment, radius and schema remain unselected.

| Scenario | Independent observation | Cleanup |
| --- | --- | --- |
|2700 headless combinations | Actual native getter IL vs separate native fixtures; same saved-state backend, original anatomy bytes | Synthetic process-local objects |
|Native binary roundtrip | Actual SmartSerializer map/Item records, IDs, C/L/N, body and unrelated parameters | Synthetic process-local objects |
|Empty A, body exported to B | Real native actions; checkpoint A owner/state and B raw anatomy/native rating, user visuals | Native actions remain |
|Load while A empty | Fresh native scene, RECOVER same ID/C/L/N, no conjured body | Ordinary save |
|Different body buried in A, then load | Current-red bound and native decay, central/raw displays, same C/L/N | Clear owned fields then save |

Offline cases additionally cover no-body/generic/busy branches, zero-param pruning, invalid schema/count rejection and cleanup roundtrip. Synthetic relocation is deliberately not described as real exhumation. Full production remains unready until remaining live and payment/coverage/UI boundaries are established.
