# Faith Probe — research-method checkpoint

Question: can one real grave use effective red-to-white conversion and extra wreath input, keeping native quality caps and central diagram consistent while raw body/organs/items remain unchanged? Does switching explicit activation off/on restore/reapply the same effects?

Existing paths: source/installed IL and160-case native offline oracle establish the input owners and decay leaf. Appearance Probe0.1.2 tests a different descriptor path and cannot supply these inputs. Direct vanilla actions change actual anatomy/items and cannot prove this effective-only mechanic. Therefore a separate minimal research plugin supplies only C/L and an explicit session-only activation flag, then executes real native rating/UI methods and inspects their actual output. No faith payment, coverage geometry, synthetic bodies/items, global skull hook or persistent schema is needed for this question. Full production remains BLOCKED; no guessed solution is promoted.

| --- | --- | --- | --- |
| Select with C0/L0 | Actual WGO.quality, GraveGUI.Redraw, raw body panel and central table children | Vanilla-equivalent label/chart, all intended seams reached | Clear session |

| Cleanup | Zero memory state and real GUI redraw | Native label/central diagram, unchanged physical hash; no save needed | Automatic on load/restart too |

After each update compare complete selected-grave physical GameRes/item-tree snapshots and currency; a subsequent-frame observation counts actual active diagram children and reads native total/raw-body widgets. Compare those to inputs actually delivered to the host, not a replacement diagram built by the harness. Native card creation, slot placement, scrolling and total text remain real consumers. Native body/organ skull values are read outside the scoped getter, not reverse-calculated from the effective result.

Transient bounds: one loaded-save/player ownership context, live idle grave_ground with a stable actual body reference, counts0..12 each. Load clears references, counts and pending work before scene restoration. No world iteration or save fields. Unselected objects are not affected. Close/reopen is an optional sanity check, not proof of every interruption path. Real zone notifications and save/faith purchase mechanics are deferred rather than bundled into this proof.
